# 企采云 · 企业级对公商城前端 MVP

企采云是一个面向企业客户的 B2B 对公采购商城前端，用于验证企业买方从“发现商品”到“提交采购订单”的完整客户端体验。

当前版本聚焦最小可用闭环：企业用户进入商城后，可以浏览商品目录、查看企业协议价和阶梯价、参与促销、批量导入采购清单、管理购物车、确认收货与开票资料、提交订单，并在订单中心查看“待审批”状态和订单快照。

本项目是前端 MVP，暂不连接真实认证、库存、支付、审批、物流或 ERP 服务。商品、客户、地址、发票和订单使用 typed mock 数据，购物车与前端创建的订单使用浏览器 `localStorage` 持久化；后续可以在不重写页面信息架构的情况下替换为真实 API。

## 技术栈

- **TypeScript 5.5**：领域类型、组件 props、服务边界和状态数据均强类型化。
- **Next.js 14 + App Router**：使用文件系统路由组织首页、目录、结算和订单页面。
- **React 18**：通过 Client Components、Context 和 hooks 管理交互状态。
- **Tailwind CSS 3.4**：负责响应式布局、设计 token、状态色和组件样式。
- **PostCSS + Autoprefixer**：处理 Tailwind CSS 构建链路。
- **Browser localStorage**：保存演示会话、购物车和本地创建订单。

项目不依赖外部 UI 组件库、图片 CDN 或后端服务；商品视觉使用 CSS 色块和品牌字标，便于后续替换真实素材。

## 功能清单

### 客户侧商城

- 商城首页：企业权益、授信额度、活动入口、品类入口、推荐商品、最近订单。
- 商品目录：关键词搜索、SKU/OEM 搜索、品类筛选、现货筛选、价格排序和空结果状态。
- 商品详情：SKU 规格、企业协议价、原价、阶梯价格、库存/交期、数量选择和加购。
- 促销中心：活动规则、有效期、活动类型和活动商品。
- 批量采购：粘贴 `SKU + 数量`，逐行匹配商品并提示不存在、不可售或格式错误的行。

### 交易主链路

- 购物车：相同 SKU 自动合并、数量调整、勾选结算、删除行、金额摘要。
- 结算：选择预置收货地址、发票档案、企业账期/对公转账，并填写备注和期望送达日期。
- 订单提交：防重复提交，生成订单号，订单进入“待审批”。
- 订单中心：按全部、待审批、处理中、已完成筛选，按订单号或商品搜索。
- 订单详情：商品和金额快照、收货/开票信息、审批时间线、再次采购。

### 账户体验

- 登录、注册、找回密码 UI，使用 mock session 模拟成功状态。
- 企业账户页：当前企业、买方用户、授信额度、账期、收货地址和发票档案。
- 响应式导航：桌面侧栏、移动端抽屉导航、全局搜索、通知和采购车数量。
- 统一空态、错误提示、Toast、加载中的交互反馈和基础无障碍标签。

## 模块划分

### 1. 应用壳层与导航

文件：`app/components/app-shell.tsx`

负责品牌侧栏、桌面/移动端响应式导航、全局搜索、通知入口、企业上下文摘要和采购车数量。页面只负责业务内容，不重复实现布局。

### 2. 领域模型与 mock 数据

文件：`app/lib/domain.ts`、`app/lib/mock-data.ts`

核心领域对象包括：

- `CompanyProfile` / `UserProfile`：企业组织和登录用户。
- `Product` / `ProductSku`：商品展示实体和真正可交易的 SKU。
- `Promotion` / `PriceTier`：活动规则、协议价和阶梯价。
- `Cart` / `CartItem`：当前企业和用户的采购草稿。
- `CheckoutState`：结算阶段的地址、发票、结算方式和备注。
- `Order` / `OrderLine`：提交后的订单和商品快照。
- `Address` / `InvoiceProfile`：预置收货地址与开票档案。

金额计算、促销折扣、阶梯价、订单状态文案和批量 SKU 解析也集中在领域层，避免页面组件各自实现业务规则。

### 3. 客户端状态与持久化

文件：`app/components/store-provider.tsx`、`app/lib/storage.ts`

`StoreProvider` 暴露产品、企业、购物车、订单、会话和通知能力。写入操作通过 typed service 风格的方法完成，页面不直接修改 mock 数据。`storage.ts` 提供 SSR 安全的 `readStorage`、`writeStorage`、`loadCart` 和 `loadOrders` 等适配器。

### 4. 商品与采购模块

文件：`app/components/product-card.tsx`、`app/components/ui.tsx`、`app/products/`、`app/bulk-buying/`

提供商品卡片、SKU 视觉、价格展示、数量步进器、筛选器和批量采购解析预览。相同 SKU 多次加入时自动合并数量，达到阶梯门槛后重新计算单价。

### 5. 结算与订单模块

文件：`app/cart/`、`app/checkout/`、`app/orders/`

结算确认收货地址、开票档案和结算条款；订单提交后生成唯一订单号和订单快照。当前 MVP 的统一规则是：**所有订单提交后进入“待审批”，买方端不显示审批/驳回按钮**。

### 6. 视觉与基础组件

文件：`app/components/icons.tsx`、`app/components/ui.tsx`、`app/globals.css`、`tailwind.config.ts`

包括 SVG 图标、按钮、金额、状态标签、面包屑、空态、商品视觉、表单标签和数量步进器。视觉基线是深海军蓝品牌导航 + 珊瑚橙促销强调 + 青绿色企业权益提示，兼顾企业场景的数据密度与电商的可发现性。

## 业务流程

```text
登录 / 当前企业上下文
          ↓
商城首页 → 分类 / 搜索 / 促销 → 商品详情
                                      ↓
                              选择 SKU 与数量
                                      ↓
                 购物车（合并数量、校验价格与库存提示）
                                      ↓
        结算（地址 → 发票 → 结算条款 → 金额确认）
                                      ↓
                         提交采购订单（防重复提交）
                                      ↓
                        订单已提交 · 待审批
                                      ↓
          审批通过后由后续服务推进履约/支付/发票流程
```

### 关键业务规则

1. 所有价格均以当前企业上下文为准，演示页展示人民币含税协议价。
2. 数量为正整数；SKU 的数量变化会重新匹配阶梯价。
3. 协议价作为基价，活动规则最多应用一条；优惠、库存、交期在结算和提交时需要重新校验。
4. 购物车不是订单，不锁定库存，也不代表采购承诺。
5. 订单提交时保存商品、SKU、单价、优惠、地址、发票和结算方式快照，后续目录变化不改写历史订单。
6. 当前 MVP 所有新订单都进入“待审批”，买方端只读展示审批状态和时间线。
7. 当前预置两条收货地址、两条发票档案；本阶段不做地址/发票 CRUD。
8. 当前不接真实支付、库存预占、物流、发票开具、审批操作或订单取消。

## 本地启动

### 环境要求

- Node.js `18.17+`
- npm `9+`

### 安装依赖

```bash
npm install
```

### 开发模式

```bash
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000)。默认演示会话已经登录到“深圳市蓝图精密制造有限公司”，可以直接体验商品、购物车、结算和订单流程。

### 生产构建与启动

```bash
npm run build
npm run start
```

`npm run build` 会执行 Next.js 生产构建、类型检查并预渲染静态页面。

### 类型检查

```bash
npx tsc --noEmit
```

项目不需要环境变量即可运行。后续接入真实 API 时，建议新增 `.env.local`，并将认证、目录、价格、购物车和订单请求放入 service adapter，而不是直接写入页面组件。

## MVP 验证清单

- 首页可以跳转到目录、促销、批量采购、采购车和订单中心。
- 商品详情可以调整数量、查看阶梯价并加入采购车。
- 相同 SKU 重复加购后，购物车数量会合并。
- 批量采购可以识别有效 SKU，并保留失败行提示。
- 结算页可以选择收货地址、发票档案和结算方式。
- 提交订单后跳转订单详情，订单状态为“待审批”，采购车已清空。
- 刷新页面后，购物车、本地创建订单和演示会话仍可从 `localStorage` 恢复。
- 桌面端侧栏和移动端抽屉导航均可用，页面不依赖横向滚动完成主流程。

## 后续演进建议

1. 先确认真实认证、企业切换和成员权限接口。
2. 接入目录、协议价、库存和促销服务，并保留现有领域类型。
3. 引入订单幂等提交、库存预占和授信校验。
4. 再接入审批工作台或 OA/ERP 回写，推进订单状态。
5. 最后补充真实支付、发票、物流、地址簿、活动配置和数据报表。
