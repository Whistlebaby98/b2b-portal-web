# ADR 0001：MVP 中所有订单先进入待审批，买方端不提供审批按钮

- 状态：已接受
- 日期：2026-09-14
- 适用范围：对公商城客户侧 MVP 的订单提交与状态展示

## 背景

对公采购通常需要满足企业内部的金额、预算、职责分离和合规要求。商城端的主要职责是让 BuyerUser 代表 CustomerOrganization 完成选品、结算信息确认和订单提交；审批则属于组织治理流程，可能由采购负责人、部门主管、财务或外部审批系统承接。

当前仍处于需求调研和前端 MVP 阶段，尚未确定每个客户组织的审批层级、金额阈值、审批人来源及与外部系统的集成协议。如果在买方端提前实现“审批/驳回”控制，容易造成角色越权、状态含义不清，并把尚未确认的组织规则固化到客户界面。

## 决策

1. 每一笔由客户侧成功提交的 Order，无论金额、商品、来源或买方职责，都先创建一个 ApprovalRequest。
2. ApprovalRequest 的初始状态统一为“待审批”。订单在审批通过前不得被展示为已确认采购或进入后续履约承诺。
3. 客户侧买方界面只展示订单的审批状态、当前节点（如已知）、时间线、提交人和可读的下一步说明；不提供“审批”“驳回”“改审批人”等审批按钮。
4. 审批动作由后续确定的审批工作台、组织管理员或外部流程服务承接。审批结果回写后，客户侧只负责按权限展示最新状态。
5. MVP 可使用模拟会话与模拟数据演示上述状态流，但必须保留订单提交、审批请求和状态查询的清晰接口边界，避免将展示状态当作真实审批结果。

## 选择理由

- **角色安全**：下单人通常不是审批人。移除买方审批控制可避免同一用户自买自批和误操作。
- **业务可扩展**：统一入口能容纳未来的金额阈值、分级审批、预算校验和外部审批，而不改变客户侧下单心智。
- **审计一致**：所有订单都有同一种初始轨迹，便于解释“订单何时提交、何时进入审批、谁做出决定”。
- **前端聚焦**：MVP 可以完整验证目录、价格、购物车、结算和订单状态体验，不需要在未定规则上构建审批工作台。

## 被考虑的替代方案

### A. 只有超过金额阈值的订单才审批

暂不采用。阈值由各 CustomerOrganization 自行配置，且当前没有可靠的组织政策、币种、税额和例外规则来源。MVP 中采用该方案会让“无需审批”的订单拥有不同生命周期，增加演示和验收分支。

### B. 买方在订单详情中直接审批或驳回

不采用。它混淆了 BuyerUser 与 Approver 的职责边界，也可能使买方绕过企业内部控制。若未来确认某一角色确实兼具审批职责，应通过明确的权限上下文和审批工作台单独设计，而不是在普通买方订单页添加按钮。

### C. 提交后直接视为已确认订单，异步补做审批

不采用。先确认后审批会让库存、额度、交付承诺和对账产生不可逆的业务承诺，审批驳回时需要补偿和回滚，风险高于当前阶段的收益。

## 影响与取舍

### 正面影响

- 客户端的订单状态和引导文案简单、一致，能明确告诉买方“已提交，等待组织审批”。
- 后续接入组织审批中心、ERP、OA 或第三方流程时，可以复用 ApprovalRequest 作为边界。
- 测试可以围绕统一的 `submitted → pending approval` 场景建立最小验收集。

### 代价与限制

- MVP 中即使是低风险或小额订单，也会显示待审批，买方可能感到流程变长。
- 在审批服务尚未接入前，订单无法在客户侧推进到已通过或履约状态；演示数据必须明确标注为模拟状态。
- 若客户组织实际没有审批制度，后续需要增加组织级策略开关或自动通过规则，并迁移已有状态语义。

## 状态边界

```text
CheckoutSession 确认
        |
        v
Order 已提交 + ApprovalRequest 待审批
        |                         \
        | 审批服务回写              | 买方取消/流程失效（若业务允许）
        v                           v
Order 已通过 / 已驳回          Order 已取消 / 已失效
```

“待审批”是订单提交成功后的业务状态，不表示支付成功、库存锁定或已安排发货。任何库存、价格、额度和促销的最终校验都必须在真正接受订单的服务边界重新执行。

## 后续验证与修订条件

当以下信息具备时，重新评估本 ADR：

- 客户组织提供了正式的审批政策、角色/节点和金额阈值；
- 明确审批动作由哪个工作台或外部系统承接，以及幂等和回写协议；
- 确定订单在审批期间对库存、价格、授信额度和促销资格的锁定规则；
- 有真实客户验证“所有订单待审批”是否会造成不可接受的转化或运营成本。

修订时应保留历史 Order 与 ApprovalRequest 的审计轨迹，不得仅通过修改前端显示将既有订单伪装成另一种状态。
